Render a .qmd document with PHP cells by naming the kernel in its front matter. No Quarto extension or other configuration is needed.

A minimal document

---title: "Fuel economy"jupyter: php---```{php}$mtcars = \Phibble\DataFrame::fromCsv(    'https://raw.githubusercontent.com/'    .'phpstats/datasets/main/csv/mtcars.csv');$mtcars;```
  • jupyter: php names the kernel by the --name that juphyter install was given. php is the default, and a kernel installed with --name php85 is named jupyter: php85.
  • A cell is a fenced block whose info string is {php}. It holds PHP without an opening tag.
  • Quarto runs the cells in order, in one PHP session per render.

Render it:

quarto render report.qmd

This writes report.html beside the document. --to chooses another format, such as --to typst for a PDF.

Quarto runs its Jupyter engine in a Python interpreter of its own choosing, which needs Jupyter in it. juphyter doctor reports whether it has one, and Python interpreters and editors covers how to choose it. CI tests Quarto 1.10.18.

Output formats

Format Command Extra requirement
HTML quarto render report.qmd None.
PDF through Typst quarto render report.qmd --to typst vl-convert for phiz plots.
PDF through LaTeX quarto render report.qmd --to pdf vl-convert for phiz plots, and rsvg-convert from librsvg.
Word quarto render report.qmd --to docx vl-convert for phiz plots. Without rsvg-convert, Pandoc warns and embeds the SVG as it is.

Typst ships inside Quarto and is the simpler PDF route. vl-convert produces the static SVG of a phiz plot. Put it on PATH, or point PHIZ_VL_CONVERT at it. Without it a plot has no SVG, and a PDF or Word document has no figure.

What each format takes from a cell’s output:

Format A phiz plot A phibble data frame
html The interactive chart, drawn by Vega-Lite in the browser. The HTML table, with the dimensions and the type row.
typst, pdf The static SVG, as a numbered figure. A typeset table, without the dimension note and the truncation footer.
ipynb The HTML embed. Nothing.

quarto render --to ipynb converts the rendered document, and Quarto’s conversion drops HTML tables and error outputs. Render to HTML or PDF when a document’s tables matter.

Cell options

Quarto’s cell options are #| comments at the top of a cell. PHP reads them as line comments.

  • #| echo: false runs the cell and hides its source.
  • #| eval: false shows the source and does not run it.
  • #| output: false runs the cell and shows no output.
  • #| error: true continues the render past a cell that throws, and keeps the traceback.
  • #| fig-cap: "..." captions the cell’s figure.
  • #| label: fig-mileage gives the figure a cross-reference label.

A captioned plot of mtcars:

$mtcars = DataFrame::fromCsv(    'https://raw.githubusercontent.com/'    .'phpstats/datasets/main/csv/mtcars.csv');Plot::of($mtcars)->aes(x: 'hp', y: 'mpg')->point();

Projects and autoloading

Quarto runs the kernel in the document’s directory. The kernel looks upward from there for vendor/autoload.php, so a document inside a Composer project can use that project’s classes and packages. A document outside any project names an autoloader with JUPHYTER_AUTOLOAD or a juphyter.json beside it. Which classes a notebook sees lists both.

In a Quarto project, each document names its kernel in its own front matter.

Freeze

execute: freeze: auto works with PHP documents. Quarto re-executes a document only when its source changes and stores the output in _freeze/. A project that commits that directory can be rendered without the packages the cells use, as long as a kernel with the document’s name is registered. Troubleshooting explains that requirement.

execute:  freeze: auto

Each render of a PHP document starts a new PHP session. Quarto does not keep a PHP kernel alive between renders. Troubleshooting covers the details.
